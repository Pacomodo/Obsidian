이 슬라이드의 코드에서 `def addN(n: Int): Int => Int = m => n + m` 부분은 **고차 함수**와 **익명 함수**를 활용하여 **함수를 반환**하는 방식에 대해 설명하고 있습니다. 이 함수는 **일급 함수(first-class function)** 개념의 중요한 예시 중 하나입니다. 아래에서 이를 더 자세히 설명하겠습니다.

---

### 1. 함수 시그니처: `def addN(n: Int): Int => Int`
```scala
def addN(n: Int): Int => Int
```
- 이 함수 **`addN`**은 정수 `n`을 인수로 받아들입니다.
- 반환 타입이 **`Int => Int`**로 되어 있는데, 이는 `addN`이 **함수를 반환**한다는 뜻입니다.
  - 반환되는 함수는 **정수를 받아서 다시 정수를 반환**하는 함수입니다.

### 2. 함수 본문: `m => n + m`
```scala
m => n + m
```
- **`m => n + m`**은 **익명 함수(anonymous function)**를 정의한 부분입니다.
- 이 익명 함수는 **`m`**이라는 정수를 입력으로 받아 **`n + m`**이라는 값을 반환합니다.
- 여기서 중요한 점은 **`n`**은 외부 함수 `addN`의 인자로 전달된 값으로, **클로저(closure)**의 개념이 적용된다는 것입니다. `n`은 `addN`이 호출될 때 그 값이 고정되며, 이후 반환된 함수에서도 계속 사용됩니다.

### 3. 동작 원리: 고차 함수와 클로저

#### 고차 함수
- **`addN`**은 **고차 함수**입니다. 고차 함수는 **다른 함수를 반환**하거나, **다른 함수를 인수로 받는 함수**를 말합니다.
- 이 경우, `addN`은 정수를 입력으로 받아, **또 다른 함수**를 반환하는 고차 함수입니다.

#### 클로저
- 반환된 함수가 사용하는 변수 **`n`**은 **클로저**를 형성합니다. 클로저는 **자신의 스코프 외부에 있는 변수**를 기억하는 함수입니다.
- 즉, `addN`이 반환하는 함수는 **`n`**을 기억하고 있다가, 이후에 `m`을 입력으로 받으면 **`n + m`**을 계산합니다.

### 4. 사용 예시

#### 예시 1: `addN(3)`
```scala
val add3: Int => Int = addN(3)
```
- `addN(3)`을 호출하면, **`n = 3`**인 상태에서 함수 **`m => 3 + m`**을 반환합니다.
- 이 반환된 함수는 `add3`에 할당되며, `add3`은 이제 **정수를 입력으로 받아서 그 값에 3을 더하는 함수**가 됩니다.
- 예를 들어, `add3(5)`는 `3 + 5 = 8`을 반환합니다.

#### 예시 2: 직접 호출
```scala
addN(3)(5)
```
- 이 코드는 **`addN(3)`**을 먼저 호출하여 **`m => 3 + m`**을 반환한 후, 이어서 **`5`**를 전달하는 방식입니다.
- 최종 결과는 **`3 + 5 = 8`**이 됩니다.

### 전체 코드 설명

```scala

```

1. **`addN` 함수 호출**:
   - `addN`에 `n`을 인수로 전달하면, 이 값은 함수 `addN` 내부에서 고정된 값이 됩니다.
   - 그 후, **`n + m`**을 계산하는 함수를 반환합니다. 이 반환된 함수는 여전히 `n` 값을 기억하고 있습니다.

2. **반환된 함수의 사용**:
   - 반환된 함수는 정수 `m`을 받아서, **`n + m`**을 계산하고 그 값을 반환합니다.
   - 이 함수는 `addN`이 호출될 때 결정된 `n` 값을 클로저로 유지하고, 이후 사용됩니다.

### 요약
- **`addN(n)`**은 **정수 `n`을 받아** `n + m`을 계산하는 함수를 반환하는 **고차 함수**입니다.
- 반환된 함수는 **클로저**로 `n` 값을 기억하고 있다가, `m`을 받아서 `n + m`을 계산합니다.
- 이는 **함수가 일급 시민(first-class function)**임을 보여주는 예시로, 함수가 변수에 할당되거나 다른 함수에서 반환될 수 있음을 나타냅니다.

- **`m => n + m`**은 **익명 함수(anonymous function)**를 정의한 부분입니다.

- **클로저**란, 반환된 함수가 **외부 스코프**에서 정의된 변수를 기억하는 특성을 말합니다.

- 예를 들어, `addN(3)`을 호출하면 `n`이 **3**으로 고정되고, 이후 반환된 함수는 `3 + m`을 계산하게 됩니다.

이 두 슬라이드는 **클로저(Closure)** 개념을 사용하여 함수가 값으로 취급되는 방식과 함수 적용이 어떻게 환경(environment)을 포함하는지 설명하고 있습니다. 특히, **FVAE** 프로그램에서 함수가 평가될 때 **클로저**의 개념을 이용하여 함수와 그 함수가 사용된 환경을 함께 관리하는 것을 다룹니다. 이를 통해 함수가 어떤 값을 참조하고 어떻게 실행되는지를 구체적으로 보여줍니다.

### 첫 번째 슬라이드: **클로저와 함수 값**

#### 프로그램

```scala
val addN = n => m => n + m;
val add3 = addN(3);
add3(5) // 3 + 5 = 8
```

1. **`addN` 함수 정의**:
   - `addN`은 두 개의 값을 더하는 **커링된 함수**입니다. 첫 번째 값 `n`을 받아, 그 값을 기억하고 두 번째 값 `m`을 받아서 **`n + m`**을 계산하는 함수입니다.
   
2. **`add3` 정의**:
   - `val add3 = addN(3)`는 `addN`에 3을 전달하여, `m`을 받아서 **`3 + m`**을 계산하는 함수를 생성합니다.

3. **`add3(5)`**:
   - `add3(5)`는 반환된 함수에 `5`를 전달하여 **`3 + 5`**를 계산하고, 결과는 `8`이 됩니다.

#### 함수 평가 과정

- **`addN(3)`**: 함수 `addN`을 호출할 때, 함수는 **`n`**을 3으로 고정한 후 **`m => n + m`** 함수를 반환합니다.
  - 이때 `n`이 **3**으로 고정되었지만, `m`은 아직 정의되지 않았습니다.

- **`add3(5)`**: 이제 `add3(5)`를 호출하면, **`n`**은 이미 **3**으로 고정되어 있기 때문에, `5`를 **`m`**에 전달하여 **`3 + 5`**를 계산합니다.

---

### 두 번째 슬라이드: **클로저와 환경**

#### 핵심 질문

- 함수는 인수로 전달되거나 반환될 때 **어떤 환경에서 정의되었는지**를 기억해야 합니다.
- 첫 번째 슬라이드에서는 `n`이 어떻게 관리되는지 설명이 없었지만, 여기서는 함수와 그 함수가 실행된 **환경(environment)**을 관리하기 위한 **클로저(closure)** 개념을 도입합니다.

#### 클로저의 정의

- 함수의 값은 단순히 `λx.e` 같은 함수의 정의뿐만 아니라, 그 함수가 **어떤 환경**에서 정의되었는지를 함께 기억해야 합니다.
- 이를 위해, 함수와 그 환경을 한 쌍으로 **클로저(closure)**로 정의합니다. 즉, 클로저는 **함수 정의와 그 함수가 사용된 환경**으로 이루어진 값입니다.

#### 환경 포함한 평가

1. **`v0 = ⟨λn.λm.(n + m), ∅⟩`**:
   - `addN` 함수가 정의될 때, **빈 환경(`∅`)**에서 함수가 정의됩니다. 따라서 `v0`는 **함수 정의**와 그 함수가 정의된 **환경**(빈 환경)을 포함하는 **클로저**입니다.

2. **`v1 = ⟨λm.(n + m), [n ↦ 3]⟩`**:
   - `add3` 함수는 `addN(3)`을 호출한 결과로 만들어집니다. 이때 **`n = 3`**이라는 환경을 포함하는 클로저가 만들어집니다.
   - 즉, `v1`은 `λm.(n + m)`이라는 함수 정의와 함께, **환경 `[n ↦ 3]`**을 포함하는 클로저입니다. 여기서 **`n`**이 **3**으로 바인딩되어 클로저의 환경에 포함됩니다.

3. **최종 평가**:
   - **`add3(5)`**를 평가하면, 클로저 `v1`을 사용하여 **`n = 3`**이 적용된 상태에서 `m = 5`를 전달하여 **`3 + 5`**를 계산하고 최종 결과 **`8`**을 얻습니다.

---

### 결론

두 슬라이드는 **클로저**가 함수의 정의와 함께 **환경**을 어떻게 관리하는지 설명합니다. 특히, 함수가 다른 함수에 전달되거나 호출될 때, 함수가 정의된 환경을 유지하여 변수의 값을 정확히 참조할 수 있도록 **클로저**를 사용합니다.

- **클로저**는 함수와 그 함수가 정의된 **환경**을 한 쌍으로 관리하여, 함수가 어디에서 어떻게 실행되었는지 기억하는 구조입니다.
- 이를 통해 **`addN`**이 호출될 때, **`n`**의 값을 3으로 고정하고, 그 이후에 **`add3`**을 통해 이 환경에서 함수가 어떻게 적용되는지를 보여줍니다.

이 슬라이드에서 지적하고 있는 문제는 **함수가 정의된 환경을 기억하지 않으면** 발생하는 **변수 참조 오류**입니다. 이 문제는 특히 **클로저(closure)**가 없는 상황에서, 함수가 외부에서 정의된 변수를 참조할 때 발생할 수 있습니다.

### 핵심 문제: **환경을 기억하지 않는 경우**

만약 함수가 자신이 정의된 환경을 기억하지 않고, 단순히 함수 본문만으로 처리된다면, 함수가 외부에서 참조하는 변수를 올바르게 처리할 수 없습니다. 이 문제를 구체적으로 살펴보겠습니다.

---

### 예제 프로그램

```scala
val addN = n => m => n + m;
val add3 = addN(3);
add3(5) // 3 + 5 = 8
```

여기서 발생할 수 있는 문제는 **`addN`** 함수가 반환하는 **중첩 함수(`m => n + m`)**에서 발생합니다.

1. **`addN` 함수**는 `n`이라는 변수를 받아, 그 값을 기억한 상태에서 **`m => n + m`**이라는 함수(중첩 함수)를 반환합니다.
2. `add3`는 **`addN(3)`**을 통해 만들어지는데, 이때 `n`의 값은 **3**으로 고정됩니다.
3. **`add3(5)`**을 호출하면 **`n`이 3으로 고정된 상태**에서 **`m = 5`**가 되어, **`n + m = 3 + 5`**가 계산됩니다.

### 문제 상황: 환경을 기억하지 않으면

만약 함수가 **자신이 정의된 환경을 기억하지 않는다면**, `add3` 함수는 `n`을 제대로 참조할 수 없습니다. 즉, `add3` 함수가 `n`의 값을 제대로 기억하지 못하고, 함수 본문에서 **정의되지 않은 변수**처럼 인식될 수 있습니다. 

#### 발생할 수 있는 문제:
- **`n`이 정의되지 않았다고 생각할 수 있음**: `add3` 함수에서 `n`이 어느 곳에서도 정의되지 않았다고 판단할 수 있습니다.
- **잘못된 값 참조**: 또는 `n`이 다른 범위에서 정의된 값으로 덮어씌워질 가능성도 있습니다.
- **결과가 예상과 다르게 나올 수 있음**: `n`을 올바르게 기억하지 못하면, 함수가 예상치 못한 결과를 반환하게 됩니다.

### 클로저(Closure)를 사용하여 문제 해결

이 문제를 해결하기 위해 함수는 자신이 정의된 **환경을 기억**해야 합니다. 이때 사용되는 개념이 **클로저(closure)**입니다.

- **클로저**는 함수와 그 함수가 **정의된 환경을 쌍으로 관리**합니다.
- 이렇게 하면 함수가 반환된 후에도 **정의된 환경에 있는 변수(`n`)**에 접근할 수 있습니다.
- 예를 들어, **`addN(3)`**에서 `n`이 3으로 고정된 상태는 클로저에 저장되고, 이후 **`add3(5)`**를 호출할 때에도 여전히 `n = 3`을 기억하고 있습니다.

### 슬라이드의 지적: 왜 환경이 중요한가?

슬라이드는 다음과 같은 상황을 지적하고 있습니다:

1. `addN` 함수는 `n`을 받아서 **`n + m`**을 계산하는 중첩 함수를 반환하지만, 이 함수는 `n`을 **정의된 환경**에서 찾아야 합니다.
2. 만약 환경을 기억하지 않고 함수만 전달되면, `n`은 어디에서 오는지 알 수 없습니다.
3. 결과적으로 함수가 **올바른 값**을 반환할 수 없으며, 이를 방지하기 위해 **클로저**가 필요합니다.

---

### 요약

함수가 정의된 환경을 기억하지 않으면, 함수가 외부에서 참조하는 변수를 제대로 처리하지 못하는 문제가 발생합니다. 구체적으로는:

1. **정의된 환경에서 변수를 참조하지 못함**: 함수가 외부의 변수를 참조할 때 그 값을 올바르게 기억하지 못함.
2. **잘못된 변수 참조**: 함수가 호출된 시점에 변수가 이미 바뀌었거나, 정의되지 않았다고 판단될 수 있음.
3. **클로저로 문제 해결**: 함수가 정의된 환경을 **클로저(closure)**로 관리하여, 반환된 함수가 외부 변수를 정확하게 참조할 수 있도록 보장해야 함.

따라서 함수가 **정의된 환경과 함께** 관리되어야, 함수가 외부 변수를 올바르게 참조하고 예상대로 동작할 수 있습니다.

---

### 1. **핵심 개념**

슬라이드는 다음과 같은 헬퍼 함수를 정의하고 있습니다:

- **이항 연산(binary operation)**: 두 개의 값을 입력으로 받아 하나의 값을 반환하는 연산입니다.
- 이 헬퍼 함수는 다음 두 가지를 인수로 받습니다:
  1. **숫자에 대한 이항 연산(op)**: 예를 들어 덧셈(`+`)이나 곱셈(`*`)이 여기에 해당합니다.
  2. **연산의 이름(x)**: 오류 메시지에서 사용하기 위한 연산자의 문자열 표현입니다.

이 헬퍼 함수는 주어진 이항 연산을 **숫자 값(`NumV`)**에 대해 적용할 수 있도록 변환해줍니다.

---

### 2. **타입 정의**

```scala
type BOp[T] = (T, T) => T
```

- **`BOp[T]`**는 **이항 연산(binary operation)**을 정의하는 타입입니다.
  - **`(T, T) => T`**는 두 개의 `T` 타입을 받아서 다시 `T` 타입을 반환하는 함수라는 뜻입니다.
  - 예를 들어, **덧셈 연산**은 `(BigInt, BigInt) => BigInt`의 형태로 정의될 수 있습니다.

---

### 3. **헬퍼 함수: `numBOp`**

```scala
def numBOp(op: BOp[BigInt], x: String): BOp[Value] = (l, r) =>
  (l, r) match
    case (NumV(l), NumV(r)) => NumV(op(l, r))
    case (l, r) => error(s"invalid operation: ${l.str} $x ${r.str}")
```

이 함수는 숫자에 대한 이항 연산과 연산자를 사용하여 **값(Value)**에 대한 이항 연산을 만들어 줍니다.

#### 3.1 **입력 인수**

- **`op: BOp[BigInt]`**: 이 항목은 **숫자(BigInt)**에 대해 이항 연산을 수행하는 함수입니다. 예를 들어:
  - 덧셈의 경우: `op = (a, b) => a + b`
  - 곱셈의 경우: `op = (a, b) => a * b`
  
- **`x: String`**: 연산자 이름을 나타내는 문자열입니다. 오류 메시지에서 어떤 연산에서 잘못된 값이 들어왔는지를 명확히 알려주기 위해 사용됩니다. 예를 들어:
  - 덧셈일 때 `x = "+"`
  - 곱셈일 때 `x = "*"`

#### 3.2 **반환값**

- 함수는 **`BOp[Value]`** 타입의 이항 연산을 반환합니다.
  - 이 반환값은 **값(`Value`)** 타입에 대해 동작하는 이항 연산입니다.

#### 3.3 **구체적인 동작**

- **`(l, r) match`**: `l`과 `r`는 두 값(Value)이며, 여기서 값의 타입을 패턴 매칭으로 확인합니다.

1. **`case (NumV(l), NumV(r))`**:
   - 두 값이 모두 **숫자(`NumV`)**라면, **주어진 이항 연산(`op`)**을 두 값에 적용합니다.
   - `op(l, r)`는 **`l`과 `r`**을 연산하고, 그 결과를 다시 **숫자 값(`NumV`)**으로 반환합니다.

2. **그 외의 경우 (`case (l, r)`)**:
   - 만약 `l`이나 `r`가 숫자가 아니라면, 오류를 발생시킵니다.
   - 오류 메시지에는 연산자(`$x`)와 잘못된 값(`$l.str` 및 `$r.str`)이 포함됩니다. 이를 통해 어떤 연산이 잘못되었는지 명확히 알 수 있습니다.

---

### 4. **헬퍼 함수 사용 예시**

이 헬퍼 함수를 사용하면 **덧셈**이나 **곱셈**과 같은 이항 연산을 간결하게 처리할 수 있습니다. 예를 들어:

```scala
val addOp = numBOp((a, b) => a + b, "+")
val mulOp = numBOp((a, b) => a * b, "*")
```

- **`addOp`**는 두 숫자를 더하는 연산을 정의한 것이고, 덧셈 연산에서 오류가 발생하면 `"+"` 연산자를 포함한 오류 메시지가 출력됩니다.
- **`mulOp`**는 두 숫자를 곱하는 연산을 정의한 것이며, 곱셈에서 오류가 발생하면 `"*"` 연산자를 포함한 오류 메시지가 출력됩니다.

이 방식으로 **덧셈(Add)**과 **곱셈(Mul)**과 같은 연산을 간편하게 처리할 수 있습니다. 이항 연산과 관련된 로직이 간소화되고, 오류 메시지도 명확하게 표시됩니다.

이 세 슬라이드는 **함수 호출 (Function Application)**이 어떻게 동작하는지 보여주며, 각 슬라이드에서 단계별로 함수가 호출되고 그 결과가 어떻게 계산되는지 설명하고 있습니다. 구체적으로, **클로저(Closure)**와 **정적 스코프(static scoping)** 개념을 사용하여 함수를 호출할 때 어떻게 환경을 관리하는지 설명하고 있습니다.
### 1. **첫 번째 슬라이드**

#### 코드 분석

```scala
def interp(expr: Expr, env: Env): Value = expr match
  case App(f, e) => interp(f, env) match
  case CloV(p, b, fenv) => ...
  case v => error(s"not a function: ${v.str}")
```

#### 동작 설명

1. **`App(f, e)`**: 함수 호출 표현식을 만났을 때, `f`는 호출된 함수이고 `e`는 전달된 인수입니다.
   - 함수 `f`는 먼저 `interp(f, env)`로 평가됩니다. 이때 함수 `f`가 **클로저(closure)**인지 확인해야 합니다.

2. **`CloV(p, b, fenv)`**: `f`가 클로저(`CloV`)로 평가되면, 클로저는 **파라미터(`p`)**, **함수 본문(`b`)**, 그리고 **정의 당시의 환경(`fenv`)**을 포함합니다.
   - 이 클로저를 통해 함수가 정의된 환경에서 함수가 실행될 수 있습니다.

3. **오류 처리**: 만약 `f`가 함수가 아니라면, 오류를 발생시키고 함수가 아니라고 알립니다.

#### 추론 규칙

$$
\sigma \vdash e_0 \Rightarrow \langle \lambda x.e_2, \sigma' \rangle
$$

이 식은 함수 표현식 `e_0`이 클로저로 평가됨을 나타냅니다. 여기서 **정의 시점의 환경**인 `σ'`이 캡처됩니다.

```scala
case App(f, e) => interp(f, env) match
  case CloV(p, b, fenv) => ...
```

#### 동작 설명

1. 첫 번째 슬라이드에서 함수 `f`는 **클로저(CloV)**로 평가되었으며, 이제 전달된 인수 `e`를 평가해야 합니다.

2. **`interp(e, env)`**: 인수 표현식 `e`를 현재 환경에서 평가하여 그 값을 얻습니다. 그 결과는 `v1`로 저장됩니다.

#### 추론 규칙

$$
\sigma \vdash e_0 \Rightarrow \langle \lambda x.e_2, \sigma' \rangle \quad \sigma \vdash e_1 \Rightarrow v_1
$$

- 이 부분에서 인수 `e1`이 `v1`으로 평가됩니다.
- 평가된 인수 값을 기반으로 함수를 적용하게 됩니다.

### 3. **세 번째 슬라이드**

#### 코드 분석 (최종 단계)

```scala
case CloV(p, b, fenv) => interp(b, fenv + (p -> interp(e, env)))
```

#### 동작 설명

1. **클로저 실행**: 클로저로 평가된 `f`는 **파라미터(`p`)**, **본문(`b`)**, 그리고 **정의된 환경(`fenv`)**을 갖고 있습니다.
   - 여기서 클로저는 `fenv`, 즉 함수가 정의된 환경에서 실행됩니다.

2. **환경 확장**: 기존의 정의 시점의 환경(`fenv`)을 확장하여, **`p`**(함수의 파라미터)에 대해 **`v1`**(평가된 인수 값)을 바인딩합니다. 즉, 함수가 정의된 환경에 새로운 변수 `p`가 추가되어 함수가 실행됩니다.

3. **본문 실행**: 마지막으로, 함수 본문(`b`)을 새로운 확장된 환경에서 실행합니다.

#### 추론 규칙

$$
\sigma'[x \mapsto v_1] \vdash e_2 \Rightarrow v_2
$$

- `σ'`는 함수가 정의된 시점의 환경입니다.
- 이 환경을 인수 값으로 확장하여, 함수 본문 `e_2`을 평가합니다.
- 최종적으로 `v2`라는 값이 도출됩니다.

---

### 요약

1. **첫 번째 슬라이드**는 함수 호출이 발생할 때 먼저 **함수 표현식**을 평가하여 클로저(Closure)를 확인하는 과정을 설명합니다.
2. **두 번째 슬라이드**는 **인수 표현식**을 평가하고 그 값을 구하는 단계를 다룹니다.
3. **세 번째 슬라이드**는 함수가 정의된 환경을 확장하여, 클로저 본문을 실행하고 최종 결과를 계산하는 과정을 보여줍니다.

이 과정에서 중요한 개념은 **클로저**와 **정적 스코프(static scoping)**입니다. 클로저는 함수가 정의될 때의 환경을 유지하고, 함수가 호출될 때 그 환경을 확장하여 실행합니다.
