###### 1. Briefly explain about the following steps for executing an instruction in the processor we learned in this course. List the required datapath elements for operations of each step.

**Sol)**
* Instruction fetch: Instruction memory에서 다음에 실행할 명령어를 가져온다.

Program Counter(PC) : 다음 실행할 명령어의 주소를 저장한다.
Instruction memory : 프로그램 명령어를 저장하는 메모리. PC를 사용해 현재 명령어를 가져온다.
Adder : PC를 4씩 증가시켜 다음 명령어의 주소를 계산한다.

* Instruction decoding: 가져온 명령어를 해석하고 필요한 Register값을 읽는다.

Instruction Memory Output: 해석해야할 Instruction
Register file: Instruction field에 기반한 Source registers(rs1, rs2)의 값을 읽는다.
Control Unit: Control signal을 만들기 위해 opcode를 해석한다.
Immediate Generator(If required): 필요한 경우 immediate value를 뽑아내고 Sign extension을 한다.

* Execution: ALU가 논리/산술 등의 연산을 수행한다.

ALU: Instruction에 따른 operation을 수행한다.
ALU Control: Instruction의 funct3, funct7, control signal등에 따라서 ALU가 어떤 연산을 해야할 지 결정해준다.
MUX: Immediate value를 사용할 지 rs2를 사용할지 고르는 역할을 한다.

* Memory: Instruction이 load나 store같이 메모리 access가 필요한 경우 수행된다.

Data memory: lw나 sw명령어인 경우 데이터를 읽거나 쓴다.
Address Input: Execution단계에서 계산된 메모리 주소(ALU 출력)을 사용함. 
Control Signals: Load instruction일때 MemRead, Store instruction일때 MemWrite.
MUX: WB단계에서 사용할 데이터가 메모리값인지 ALU값인지를 결정.

* Write-back: 연산 결과(ALU Result 또는 메모리 값)을 rd에 저장함.

Register file: 결과 값을 rd에 기록함.
MUX: 메모리 값과 ALU Result 중 WB단계에서 기록할 값을 선택함.
Control signal(Regwrite): Register file에 값을 기록할지 결정함.

###### 2. For the single-cycle processor design, we do NOT consider I-type instructions such as `addi` and `andi`. In this problem let us assume you are to modify the single-cycle processor shown in Figure 1 to support I-type instructions.

(a) What additional logic blocks, if any, are needed to add I-type instructions to the single-cycle processor shown in Figure 1? List any required logic blocks and explain their purpose.
**Sol)**
I-type 명령어를 지원하기 위해서는 Immediate Generator와 MUX가 필요하다.
I-type명령어는 Immediate value가 필요하다. Immediate Generator는 Instruction의 20bit~31bit field에서 값을 추출하여 Sign extension을 한다.
또한, R-type명령어와 I-type명령어를 구분하기 위해서 MUX가 필요하다. I-type 명령어는 Register value가 아니라 Immediate value를 ALU의 두번째 입력으로 사용하므로, MUX를 통해 이를 적절히 구분하여 ALU로 전달한다.

(b) List the values of the signals generated by the control unit for `addi`. Explain the reasoning for any “don’t care” control signals.
**Sol)**
RegWrite : 1, 결과를 레지스터에 기록하므로 활성화된다.
ALUSrc : 1, `addi`는 Immediate value를 사용하므로 활성화된다.
MemRead : 0, `addi`는 메모리에서 값을 읽지 않는다.
MemWrite : 0, `addi`는 메모리에서 값을 기록하지 않는다.
MemtoReg : 0, `addi`는 ALU output에서 결과를 읽어온다.
ALUOp : ADD, 두 입력 값을 더해야 한다.
Branch : 0, `addi`는 Branch instruction이 아니다.
PCSrc : Don't Care, `addi`는 PC update에 관여하지 않으므로 중요하지 않다.

###### 3. Let us assume that the clock period of the single-cycle processor shown in Figure 1 is 1000 ps. Consider the addition of a multiplier to the CPU. This addition will add 250 ps to the latency of the ALU, but will reduce the number of instructions by 4% (because there will no longer be a need to emulate the multiply instructions).

(a) What is the clock cycle time with this improvement?
**Sol)**
$$
\begin{align}
T_{\text{clock new}} &= T_{\text{clock original}} + \text{Added ALU latency} \\
\Rightarrow T_{\text{clock new}} &= \boxed{ 1250\text{ ps} }
\end{align}
$$
(b) What is the speedup achieved by adding this improvement?
**Sol)**
Single cycle processor에서 실행시간은 Clock cycle time과 Instruction count(IC)에 비례 하므로,
$$
\begin{align}
T_{\text{exe before}} &\propto 1000\text{ ps}\times \text{IC} \\
T_{\text{exe after}} &\propto 1250\text{ ps}\times 0.96\times \text{IC} \\ 
\text{Speed up} &= \frac{T_{\text{exe before}}}{T_{\text{exe after}}} \\
&=\frac{1000}{1200} \approx 0.83333
\end{align}
$$
따라서, 약 $16.667$%의 성능 저하가 일어난다.

(c) What is the longest delay by the newly added multiplier to result in performance improvement at least?
**Sol)**
성능 개선이 이루어지려면, $T_{\text{exe new}}$가 다음과 같은 조건을 만족해야 한다.
$$
\begin{align}
T_{\text{exe before}} &\geq T_{\text{exe new}} \\
T_{\text{clock original}}\times \text{IC} &\geq T_{\text{clock new}}\times 0.96 \times \text{IC} \\
T_{\text{clock original}} &\geq (T_{\text{clock original}} +T_{\text{delay}})\times 0.96  \\
0.04\times T_{\text{clock original}} &\geq 0.96\times T_{\text{delay}} \\
\frac{4}{96}\times 1000\text{ ps} &\geq T_{\text{delay}} \\
T_{\text{delay}} &\leq 41.667 \text{ ps}
\end{align}
$$
따라서, 성능 개선이 이루어질 수 있는 가장 긴 Delay는 $41.667 \text{ ps}$이다.

###### 4. In this problem we examine how pipelining affects the clock cycle time of the processor. Problems in this exercise assume that individual stages of the datapath have the following latencies. Also, assume that instructions executed by this processor are broken down as follows.

|   IF   |   ID   |   EX   |  MEM   |   WB   |
| :----: | :----: | :----: | :----: | :----: |
| 250 ps | 400 ps | 250 ps | 300 ps | 200 ps |

| ALU/logic | Jump/Branch | Load | Store |
| :-------: | :---------: | :--: | :---: |
|    45%    |     20%     | 20%  |  15%  |
(a) What is the clock cycle time in a pipelined and non-pipelined processor?
**Sol)**
Non-pipelined의 경우 모든 단계를 한 사이클 내에서 실행해야하므로, 가장 레이턴시가 큰 경로의 시간이 Clock cycle time이 된다.
즉, $250+400+250+300+200 = 1400 \text{ ps}$가 Clock cycle time이 된다.
Pipelined의 경우 각 단계에서 실행되므로 레이턴시가 가장 긴 단계의 레이턴시가 Clock cycle time이 된다.
즉, $400 \text{ ps}$가 Clock cycle time이 된다.

(b) What is the total latency of a `ld` instruction in a pipelined and non-pipelined processor?
**Sol)**
Non-pipelined의 경우 `ld` 명령어가 모든 단계를 거쳐야하므로 $1400 \text{ ps}$이다.
Pipelined의 경우 5개의 Pipeline단계를 모두 거치는 시간과 동일하므로 $5\times 400\text{ ps} = 2000\text{ ps}$이다.

(c) If we can split one stage of the pipelined datapath into two new stages, each with half the latency of the original stage, which stage would split and what is the new clock cycle time of the processor?
**Sol)**
New clock cycle time이 적어지기 위해서는 Latency가 가장 긴 단계를 나누는 것이 적합하므로, ID를 2개의 $200 \text{ ps}$단계로 나눈다.
새로운 Clock cycle time은 $\max(\text{IF}, \text{ID}_{1}, \text{ID}_{2}, \text{EX}, \text{MEM}, \text{WB}) = 300\text{ ps}$가 된다.

(d) Assuming there are no stalls or hazards, what is the utilization of the data memory?
**Sol)**
MEM단계는 `ld`, `sw` 등의 명령어에서만 사용되므로, $20 + 15 = 35$%가 된다.

(e) Assuming there are no stalls or hazards, what is the utilization of the write-register port of the register file?
**Sol)**
Register file의 Write-register port는 Register를 사용하는 명령어에서 사용된다. Jump/Branch Instruction은 일반적으로 레지스터를 사용하지 않고, Store Instruction은 레지스터가 아니라 메모리에 데이터를 저장하므로, $45 + 20 = 65$%가 된다.
