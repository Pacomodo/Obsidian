### What is LCA?

트리 위에서 최소 공통 조상(LCA - Lowest Common Ancestor)을 구하는 문제입니다.
![[graph.png|center|400]]
다음과 같이 트리가 그려져 있다고 해봅시다.

최소 공통 조상이란, 두 노드 모두의 조상이 되는 노드들 중 가장 높이가 낮은 노드를 뜻합니다.

예를 들어, 12와 15의 공통 조상들은, 5, 2, 1이 있고, 이 중 가장 높이가 낮은 노드는 5번 노드입니다.
즉, 5번 노드가 12와 15의 LCA가 됩니다.

### Naive Method

#### Algorithm

이를 구하는 가장 쉬운 방법은 다음과 같습니다.

편의 상 두 노드를 $a, b$라고 합시다.

1. 루트에서 $a$까지 가는 경로를 DFS나 BFS로 찾는다. (트리이기 때문에 경로는 유일합니다.)
2. 루트에서 $b$까지 가는 경로를 DFS나 BFS로 찾는다.
3. 두 경로를 앞(루트 노드)에서부터 하나씩 비교해가며 공통되지 않은 부분이 나올 때까지 확인한다.
4. 마지막으로 나오는 공통 노드가 LCA가 된다.

![[graph.png|center|300]]
위의 예시라면, 1부터 12까지의 경로는 $[1, 2, 5, 12]$이고, 1부터 15까지의 경로는 $[1, 2, 5, 11, 15]$이기 때문에, 마지막으로 나온 공통 노드 $5$가 LCA가 됩니다.

#### Time Complexity

최악의 경우를 생각해봅시다.
![[graph (1).png|center|300]]
다음 그림과 같이 노드가 $100000$개 있는 일직선 모양의 트리가 있다고 해봅시다.

100000번 노드와 99999번 노드의 LCA를 구한다고 해봅시다.
위의 방법으로는 **하나의 노드 쌍마다** $\mathcal{O}(2N) = \mathcal{O}(N)$의 시간 복잡도가 소요됩니다.

#### Implementation

구체적인 구현 방안은 다음과 같습니다.

DFS할 때 경로 배열을 통채로 함수 인자로 넣어서 전달하는건 비효율적입니다.

배열이 달라지기 때문에 경로 배열을 복사할 수 밖에 없고, 이 과정에서 Cost가 소요되기 때문입니다.

일반적으로 DFS나 BFS를 할 때 특정 경로를 찾아내는 방법은 Parent라는 방법으로 구현합니다.

`Parent[i] = i번 노드의 부모`라고 저장하고, DFS할 때 다음과 같은 방법으로 각 노드의 부모를 저장합니다.

```python
def dfs(now_node):
	for below_node in graph[now_node]:
		if below_node == parent[now_node]: continue
		parent[below_node] = now_node # 저장
		# do something
	return
```

이후 `Parent`배열을 이용하여 도착점부터 루트까지 거꾸로 올라갑니다.
```python
path = []
while parent[node] != -1:
	path.append(node)
	node = parent[node] # 거꾸로 올라가기
```

이러면 `path`배열에 거꾸로된 경로 배열이 저장됩니다.

### What is Sparse Table?

스파스테이블(희소 배열)은 특정한 구간 쿼리 문제(더 나아가 다른 방법으로도 응용할 수 있는)를 빠르게 해결할 수 있는 전형적인 자료구조입니다.

주요 특징은 다음과 같습니다.

- 누적합처럼 전처리 과정을 거침. 전처리 과정에 $\mathcal{O}(N\log N)$이 소요.
- 쿼리를 처리하는데 $\mathcal{O}(\log N)$ 또는 $\mathcal{O}(1)$이 소요.
- 구간 업데이트가 없음. (배열은 **고정**되어있어야 함.)

#### Implementation

다음과 같은 2차원 배열을 선언합시다.
$$st[i][j] = \text{ 구간 쿼리 }[j, j+2^{i})$$
이 전처리 배열은 $j$에서 시작해서 $j+2^{i}$로 끝나는 구간 쿼리에 대한 답입니다.

DP처럼 생각할 수 있는데, 구간 쿼리에 대한 답을 2개로 쪼갤 수 있습니다.

즉, $[j, j+2^{i-1})$랑 $[j+2^{i-1}, j+2^{i})$로 구간을 쪼갤 수 있으므로, 이 배열을 다음과 같이 채울 수 있습니다.
$$
st[i][j] = g(st[i-1][j],  st[i-1][j+2^{i-1}])
$$

#### Apply

만약 **구간 합**과 같은 경우라면, 구간의 길이를 이진수처럼 생각하여 구간을 쪼개어서, 미리 전처리 해놓은 $st[i][j]$값들을 더해주면 됩니다.

즉, 구간이 $[3, 15)$라면, $[3, 3+8)$, $[11, 11+4)$와 같이 2개로 쪼갤 수 있으므로 $st[3][3]$과 $st[2][11]$로 구할 수 있습니다.

따라서 이 경우 쿼리 당 구간 길이의 로그만큼의 시간이 소요됩니다.($\mathcal{O}(\log N)$)


구간 내 **최솟값**을 구하는 문제라면 굳이 구간을 이진수처럼 쪼갤 필요가 없습니다.

이 경우 구간을 겹치도록 하는 적당한 두 값에 대해서 $\min$값을 취해주면 됩니다.
$[3, 15)$라면 $[3, 3+8)$, $[7, 7+8)$, 즉, $\min(st[3][3] ,st[3][7])$이 답이 됩니다.

이 경우 쿼리 당 $\mathcal{O}(1)$이 소요됩니다.


구간을 물어보는 함수가 위와 같이 겹쳐도 같은 값이 나오는 성질을 가지고 있다면, 모두 위와 같이 $\mathcal{O}(1)$에 해결할 수 있습니다.

이런 함수들의 예시로는 min, max, gcd, or, and 들이 있습니다.

#### How to use in LCA?

이제 위의 자료 구조를 LCA를 구하는데에 써봅시다.

위에서 이야기한대로 나이브한 방법을 사용하면 하나의 노드 쌍이 주어질 때마다 $\mathcal{O}(N)$에 해결됩니다.

스파스테이블을 이용한다면 이걸 쿼리 당 $\mathcal{O}(\log N)$에 해결할 수 있습니다!!!

일단 DFS를 한번 합니다.(이건 Parent배열을 만들어야 되서 어쩔 수 없습니다.)

`parent`배열의 의미를 생각해보면, `parent[i]`가 `i`번 노드의 부모, 즉, `i`번 노드 **한칸 위**의 노드 라고 생각할 수 있습니다.

스파스테이블을 구성할 때 나왔던 2의 거듭제곱 아이디어처럼, **2, 4, 8, 16, ...** 칸 위의 노드들을 생각해봅시다...

즉, 다음과 같이 테이블을 정의합시다.

$$
st[i][j] = j\text{번 노드에서 }2^{i}\text{칸 위로 올라갔을 때의 노드}
$$

이 테이블을 이제 전처리 해봅시다. 전처리는 다음과 같이 할 수 있습니다.

$$
st[i][j] = st[i-1][st[i-1][j]]
$$
즉, $2^{i-1}$칸 위로 올라간 뒤에 다시 $2^{i-1}$칸 위로 올라가면 $2^{i}$칸 올라간 것과 동일하므로 저렇게 테이블을 채울 수 있습니다.

구현의 편의 상 루트노드의 parent는 자기 자신이라고 합시다.

저렇게 스파스 테이블을 채우고 난 후에, 다음과 같은 방법으로 LCA를 빠르게 구할 수 있습니다.

1. 두 노드의 깊이가 다르다면 깊이를 서로 맞춰줍니다.(즉, 깊이가 낮은 쪽을 높은쪽으로 **올려**줍니다. 올려줄때 $st[i][j]$를 사용해서 올립시다.)
2. 깊이를 서로 맞췄다면 두 노드가 같은지 확인합시다.
	1. 두 노드가 같다면 그게 최소 공통 조상입니다.
3. 다르다면 $2^{20}, 2^{19}, 2^{18}, \dots$순으로 크게 크게 동시에 올립니다.
	1. 만약 두 노드가 서로 같다면 너무 크게 올린것입니다.(너무 크게 올리면 루트노드로 같아지므로....)
	2. 그렇게 두 노드가 다를때 올립니다.
4. 3번 과정을 반복합니다. 그러면 두 노드가 LCA를 한칸 남겨두기 직전까지 올라갑니다.
5. 이후 둘 중 하나를 한칸 올리면 LCA를 찾을 수 있습니다.
