>[!note]
>Database is a collection of **persistent, interrelated, and integrated data**
>that is used by the application systems of **some given enterprise**.

Persistent - 프로그램을 Shutdown하면 결과가 날아가는 것과 다르게, Database는 그 데이터가 Disk에 지속적으로 저장됨.
Integrated -각 시스템마다 개별의 파일을 사용한다고 하면 그 파일에는 중복된 정보가 존재하고, 이는 불필요하다.
Interrelated - 한 시스템에 주소가 바뀐다면 모든 파일에 적용이 되야함.

DBMS의 여러 가지 문제들.
Data redundancy and inconsistency - 하나의 데이터가 여러 개의 파일에 중복해서 있는데, 그 데이터의 값이 모두 다르다면 어떤 데이터가 원본이냐?
Difficulty in accessing data - 서울에 사는 직원에 대한 데이터가 여러 개의 파일로 분산되어 있다면, 서울에 사는 직원을 모두 알아내고 싶을 때 어떻게 할 것인가?
Data isolation - 파일이 포맷이 다르고, 그 파일을 지원하는 OS가 서로 다르다면?
Integrity problems - 은행에 돈을 빼는 상황을 생각해보자. 통장은 잔액이 음수가 되면 안된다는 제약이 걸린다. 마이너스 통장은 음수가 가능한데 통장마다 다르다. Integrity constraints를 따로 따로 설정하는 것이 번거롭니다.
Atomicity of update - 하나의 트랜잭션은 All or nothing.
Concurrent access - 수강신청의 예시. 데이터의 동시 접근성
Security problems - 데이터를 누가 접근할 것인가에 따라 계층을 정해주어야 함.

Data Dependency problem - 어떤 프로그램이 데이터에 의존하는 구조로 작성되었다면, 데이터의 형식이 바뀌면 그 프로그램도 교체해 주어야 함.

Data dependence problem을 해결하기 위해서는 데이터를 통합시킨 후 각 시스템에서 원하는 데이터만 보여주도록 하면 됨.

데이터 추상화의 3가지 level 
physical - 데이터가 어떻게 물리적 장치에 실제로 저장되는 가. 레코드와 블록이 디스크에 어떻게 저장되고
logical - 어떤 데이터가 저장되는가. 그리고 그 데이터들 간의 관계. 데이터베이스에서는 ER-model을 사용하여 데이터의 유형과 그 사이의 관계를 정의함. 데이터의 일관성과 무결성을 유지하기 위한 제약조건 설정.
view - 전체 데이터 베이스의 어떤 부분을 보느냐. 보안 목적에 의해 다양한 관점에서 데이터 베이스를 볼 수 있음.

인사부, 총무부, 복지부가 모두 한 직원의 데이터를 다르게 바라볼 수 있음. 이는 View level에 해당함. 이 데이터사이의 관계나 어떤 유형으로 저장할 것인가가 Logical level. 이 데이터가 Disk에 실제로 어떻게 저장될 것인가가 Physical level임.

Schema - the logical structure of the database.
