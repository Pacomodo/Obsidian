### **Linux에서의 시스템 호출 (시스템 호출 루틴 포함)**

시스템 호출(System Call)은 사용자 공간(user space)에 있는 응용 프로그램과 커널(kernel) 사이의 중요한 인터페이스입니다. 시스템 호출을 통해 사용자 응용 프로그램은 파일 읽기/쓰기, 메모리 할당, 프로세스 관리 등과 같은 커널 서비스와 하드웨어 자원에 접근할 수 있습니다. 사용자 모드에서 실행되는 응용 프로그램은 직접 하드웨어나 시스템 자원에 접근할 수 없으므로 시스템 호출을 통해 커널에 필요한 작업을 요청하게 됩니다.

### **시스템 호출의 동작 방식**

#### 1. **사용자 모드 vs. 커널 모드**

- **사용자 모드 (User Mode)**: 응용 프로그램이 실행되는 환경으로, 시스템 자원에 대한 제한된 접근 권한을 가집니다. 운영체제는 사용자 프로그램을 격리하여, 프로그램이 시스템의 다른 부분에 영향을 미치지 않도록 보호합니다.
  
- **커널 모드 (Kernel Mode)**: 커널은 시스템의 하드웨어와 모든 자원에 완전한 접근 권한을 가지고 있습니다. 시스템 호출이 발생하면, CPU는 사용자 모드에서 커널 모드로 전환되며, 커널은 높은 권한을 가지고 작업을 처리합니다.

응용 프로그램이 커널 모드로 전환하기 위해서는 **트랩(trap)** 또는 **인터럽트(interrupt)**라는 메커니즘을 사용합니다. 이를 통해 응용 프로그램이 직접 하드웨어를 제어하거나 커널의 중요한 부분을 수정하지 못하게 됩니다.

#### 2. **시스템 호출의 흐름 (호출 루틴)**

시스템 호출이 실행될 때 일어나는 과정을 다음과 같이 요약할 수 있습니다:

**단계 1: 사용자 애플리케이션이 래퍼 함수 호출**  
대부분의 시스템 호출은 `libc`와 같은 표준 C 라이브러리의 **래퍼 함수(wrapper function)**를 통해 호출됩니다. 예를 들어, `read()` 함수는 파일을 읽기 위한 시스템 호출(`sys_read`)을 감싸는 래퍼 함수입니다. 이 함수는 시스템 호출의 복잡성을 사용자에게 감추고, 쉽게 시스템 호출을 사용할 수 있도록 해줍니다.

```c
ssize_t read(int fd, void *buf, size_t count);
```

위 함수는 파일 디스크립터에서 데이터를 읽기 위해 사용되며, 내부적으로 시스템 호출을 트리거합니다.

**단계 2: 트랩 명령어/소프트웨어 인터럽트 발생**  
래퍼 함수는 CPU에 **트랩(trap)** 또는 **소프트웨어 인터럽트**를 발생시켜 사용자 모드에서 커널 모드로 전환합니다. 예를 들어, x86-32 아키텍처에서는 `int 0x80` 명령어가 시스템 호출을 위해 사용됩니다.

x86-64 아키텍처에서는 **`syscall`** 또는 **`sysenter`** 명령어가 사용되어 커널 모드로 전환됩니다. 이 명령어는 커널의 인터럽트 핸들러에 의해 처리되며, 커널은 이후 시스템 호출을 처리하게 됩니다.

**단계 3: 시스템 호출 디스패치**  
커널 모드로 전환된 후, CPU는 전달된 시스템 호출 번호를 기반으로 해당하는 시스템 호출 핸들러를 찾습니다. 리눅스 커널은 **`sys_call_table`**이라는 테이블을 유지하며, 이 테이블은 시스템 호출 번호와 각각의 시스템 호출 핸들러 함수를 매핑하고 있습니다.

예를 들어, 사용자가 `read()` 함수를 호출하면, 시스템 호출 번호가 `sys_read` 함수에 매핑됩니다.

**단계 4: 커널 모드에서의 실행**  
커널은 요청된 시스템 호출 핸들러(`sys_read` 등)를 실행하여 필요한 작업을 처리합니다. 파일에서 데이터를 읽거나 메모리를 할당하는 등의 작업이 수행됩니다.

**단계 5: 사용자 모드로 반환**  
시스템 호출 핸들러가 작업을 완료하면, 그 결과 값(예: 읽은 바이트 수)을 호출한 사용자 애플리케이션으로 반환합니다. 이후 CPU는 다시 커널 모드에서 사용자 모드로 전환됩니다.

### **64비트 리눅스 시스템에서의 시스템 호출 루틴**

64비트 리눅스 시스템에서의 시스템 호출 처리는 다음과 같이 요약됩니다:

1. 사용자 애플리케이션은 `read()`와 같은 래퍼 함수를 호출하며, 내부적으로 `syscall` 명령어를 사용합니다.
2. `syscall` 명령어는 CPU를 커널 모드로 전환하고, 시스템 호출 번호와 매개변수를 레지스터에 전달합니다.
3. 커널의 인터럽트 핸들러는 시스템 호출 번호에 맞는 핸들러를 `sys_call_table`에서 찾아 실행합니다.
4. 커널에서 `sys_read`와 같은 시스템 호출 핸들러가 실행되어 요청된 작업을 수행합니다.
5. 작업이 완료되면 결과 값이 사용자 애플리케이션으로 반환되고, CPU는 사용자 모드로 전환됩니다.

### **예시: `read()` 시스템 호출 루틴**

`read()` 시스템 호출을 통해 파일 디스크립터에서 데이터를 읽을 때 일어나는 과정은 다음과 같습니다:

1. 사용자 애플리케이션이 `read(fd, buf, count)`를 호출합니다.
2. `read` 함수는 `syscall` 명령어를 사용해 커널에 시스템 호출을 요청합니다.
3. 커널 모드로 전환된 후, 커널은 시스템 호출 번호를 확인하고, `sys_read` 시스템 호출 핸들러를 실행합니다.
4. 커널은 파일 디스크립터에서 데이터를 읽고, 해당 데이터를 사용자 공간의 버퍼에 복사합니다.
5. 읽은 바이트 수가 사용자 애플리케이션으로 반환되고, CPU는 다시 사용자 모드로 전환됩니다.

### **시스템 호출 테이블 (`sys_call_table`)**

**시스템 호출 테이블**은 시스템 호출 번호를 해당 핸들러 함수와 매핑하는 커널 내의 배열입니다. 이 테이블은 시스템 호출이 발생했을 때, 해당 번호에 맞는 핸들러 함수가 실행되도록 합니다.

예를 들어, `syscall_64.tbl` 파일에서 다음과 같은 항목이 있을 수 있습니다:

```
__NR_read   0   read  sys_read
```

이 항목은 `__NR_read` 시스템 호출 번호가 들어오면, 커널이 `sys_read` 함수를 실행하도록 설정합니다.

### **자주 사용되는 리눅스 시스템 호출**

다음은 리눅스에서 자주 사용되는 시스템 호출입니다:
- **`read()`**: 파일 디스크립터에서 데이터를 읽음.
- **`write()`**: 파일 디스크립터에 데이터를 씀.
- **`open()`**: 파일을 엶.
- **`close()`**: 파일 디스크립터를 닫음.
- **`fork()`**: 프로세스를 복제하여 새로운 프로세스를 생성함.
- **`execve()`**: 현재 프로세스의 실행 파일을 대체함.
- **`wait()`**: 자식 프로세스의 상태 변화를 대기함.
- **`exit()`**: 현재 프로세스를 종료함.

### **결론**

시스템 호출은 사용자 공간과 커널 공간 사이에서 중요한 역할을 합니다. 시스템 호출 루틴을 통해 커널은 사용자 프로그램의 요청에 따라 파일 I/O, 메모리 관리, 프로세스 관리 등의 작업을 수행할 수 있습니다. 이를 통해 사용자 프로그램은 안전하게 커널의 자원을 사용할 수 있습니다.
